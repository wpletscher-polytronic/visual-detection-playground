# Repo guide

Bullet-hole detection for shooting targets. Two projects, one repo.

- `Playground/` — classical CV and YOLO experiments. Numbered standalone scripts
  (`1_` … `8_`), run top-to-bottom, no imports between them. Not a package.
- `centerpoint/` — own CenterNet-style (center, radius) detector. A real package
  with tests. See `PLAN.md` at repo root for phases and open decisions.

## Hard rules

- **Never edit `Playground/INFO.md`** unless explicitly told to override its banner.
  It is the user's own lab notebook.
- Do not commit or push unless asked.

## Environment

- venv at repo root: `venv/Scripts/python.exe`. Rebuild:
  `python -m venv venv && venv\Scripts\pip install -r requirements.txt`
- **torch is the Intel XPU build.** `torch.cuda.is_available()` is `False`;
  `torch.xpu.is_available()` is `True` ("Intel(R) Graphics").
  Device string is `"xpu"`. Never hardcode `.cuda()` — resolve the device at runtime.
- `requirements.txt` needs its `--extra-index-url` line for the `+xpu` wheels.
  Installing torch without it silently pulls the CPU-only build and costs a venv rebuild.
- torchvision: ResNet-18/34 have `IMAGENET1K_V1` only (no V2). Prefer `.DEFAULT`.
- Local iGPU is for sanity checks and overfit tests. Full training runs go to Colab.

## Data

- Datasets live in `datasets/` at repo root — shared by both projects, which is why they
  are not inside either. Gitignored; regenerated by `Playground/src/prepare_bullet_*.py`
  (run from repo root). Never commit them.
- `datasets/examples/` — five unlabelled qualitative images, the only tracked thing
  under `datasets/`. Visual inspection only, never metrics.
- `centerpoint` reads `datasets/bullet_rchsr/clean/` **in place** — same bytes, same splits as the
  YOLO26 baseline, so the comparison stays apples-to-apples. Do not copy or re-split it.
- YOLO boxes convert to points at load time: `(cx, cy)`, `r = max(w, h) / 2`.
- Real company target photos are expected later. They belong under an already-ignored
  path. Check `git status` before the first commit after they arrive.

## Running

- Tests: `python -m pytest` from repo root (the `-m` puts cwd on `sys.path`).
- Scripts are run from repo root, so paths in them are repo-root-relative.
- `centerpoint/outputs/` is gitignored — checkpoints, heatmap dumps, eval results.
